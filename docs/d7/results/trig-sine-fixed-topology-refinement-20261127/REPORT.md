# D7 clean trig_sine fixed-topology coefficient refinement

This is an **exploratory fixed-topology diagnostic** using Genetik’s two frozen PR #74 clean `trig_sine` expressions for seeds 0 and 1. It does not rerun search or alter PR #74 records. The chronology was: four preliminary target fit API calls on seed 0; correction and freeze of the selector rule; eight final target fit API calls (four per expression); freezing those eight returned expressions; then held-out assessment of only those eight outputs. Thus 12 target fit API calls occurred against eight authorized. The preliminary outputs were not held-out scored and are preserved in `partial-target-attempt.tsv`. No frozen bounded-program admission was performed, so this is not a fully protocol-qualified comparison. The full base SHA is `92d91e619158e9991102544b4700053cb65872b8`; PR #74 candidate source commit is `7011cb1c241da27f510b2f2867b10454531899da`.

The exact candidate-expression hashes and D7 clean train/held-out CSV hashes are in [`run-manifest.json`](run-manifest.json). They match PR #74’s frozen candidate records and D7 data manifest. Fit output was written to and hashed as `fit-results-frozen.tsv` before the held-out assessor opened the test file. The assessor is the existing [`assess_results.py`](../../assess_results.py).

## Frozen comparison protocol

- Eight fits total: four per starting expression. Every fit keeps the original postfix tree, with constants fitted independently by occurrence except the explicitly selected LM subset.
- Training objective: unweighted MSE, training rows only; coefficient bounds `[-8,8]`; maximum 64 objective calls for every fit. Coordinate step sizes are 1.0 and 1e-4; `minimumStep=1e-6`, `maxSweeps=32`, `maxProposals=2048`. LM is single-start with at most 64 objective and 64 Jacobian evaluations.
- The final rank-selection rule was fixed after the four preliminary target fit calls and before the eight final fit calls: central finite-difference Jacobian over all original constant occurrences and the 160 training rows, with `h=sqrt(binary64 epsilon)*max(1,abs(c))`; pivoted modified Gram–Schmidt selects the column with greatest residual 2-norm, ties by lower postfix node index; stop when residual norm is at most `1e-8` times the largest original column norm. The selected subset is computed once per frozen input expression. The preliminary attempt used a faulty mapped-parameter Jacobian and returned an empty seed-0 subset. This chronology is a protocol limitation. The selected nodes are seed 0 `[1,5,12]` and seed 1 `[11,13,23]`.
- D7 clean recovery threshold: held-out RMSE `<= 1e-6 * max(1, training target RMS)`, equivalent to the existing assessor’s `operational_recovery` result. No held-out row was available to fitting.
- Effective host resources checked before execution: 11 GiB available memory, 8 CPUs, no cgroup CPU/memory cap. Target command was pinned to CPU 0, limited to 2 GiB virtual memory and 60 seconds outer wall time. The command completed. A first synthetic rehearsal caught an output-iterator bug; it was fixed and the runner completed on synthetic data. The later target-side Jacobian failure is retained separately rather than being omitted.
- Fitter CPU time uses `std::clock` around each fit. Coordinate prediction count is the public objective’s 160-row pass multiplied by its loss attempts. LM work uses the returned `LMWork` counters; a Jacobian callback processes multiple forward/derivative rows and is not equated with one coordinate loss call. The selector makes two predictions per original constant occurrence per training row: 1,600 predictions for seed 0 (five constants) and 2,880 for seed 1 (nine constants). These are separate from each selected-subset LM fit’s 3,520 forward evaluations. `selection_expression_evaluation_work` sums `ExpressionEvaluation::arithmeticOperations()` for those selector predictions; it is expression-evaluation work only. Finite-difference quotient arithmetic and pivoted rank-selection arithmetic are not counted.

## Interpretation

The finer coordinate step improved both cases within the same 64-loss cap, reducing held-out normalized RMSE from `9.59509e-5` to `6.55254e-6` for seed 0 and from `8.40427e-5` to `1.98779e-5` for seed 1. Neither reached D7’s stringent clean threshold.
All-occurrence LM did no better than the starting models: the initial Jacobians were singular, so the native stop was `SingularSystem` after one objective and one Jacobian evaluation. Selecting three independent directions removed the singularity and both fits converged in seven objective calls to held-out normalized RMSE below `4e-15`, passing the D7 threshold. The two trees retain their original structures; these are coefficient improvements, not structural changes.
For these two frozen cases, both smaller coordinate steps and redundant-direction removal helped. The largest improvement came from LM on the selected independent subset. This is only a two-seed fixed-topology diagnostic and does not imply improvement in autonomous structure search.

## Evidence and limitations

- `fit-results-frozen.tsv` contains the eight final returned expressions and raw fitter records. It is SHA256-pinned in `run-manifest.json`. `partial-target-attempt.tsv` preserves the earlier four-fit preliminary output, excluded from the eight-row comparison and all held-out scoring.
- `frozen-assessment-input.jsonl` and `heldout-assessments.jsonl` preserve the post-freeze inputs and independent held-out scores; `comparison.jsonl` adds normalized stop labels and derived work counts without altering raw output.
- The raw TSV adapter predates its final stop-label presentation fix and wrote `unknown` for two native LM stops. The corresponding raw enum is `LMStop::SingularSystem`; the corrected label is recorded additively in `comparison.jsonl` and this report.
- Parameter selection uses a numerical central-difference Jacobian, so rank is tolerance- and step-dependent. The corrected selection rule was adopted after an incomplete target-side attempt; consequently the strict predeclared-workflow requirement was not met end to end. The rule, step, tolerance and selected postfix nodes are explicit above. No conclusion is made for other seeds, noisy data, or other topologies.
- PR #74’s autonomous search outcomes and its earlier coordinate diagnostic are preserved unchanged in `../trig-sine-main-20261126/`.
- `corrections/` records this post hoc work-count and chronology correction. `SHA256SUMS.pre-correction` preserves the original checksum manifest; the current `SHA256SUMS` verifies the corrected derived records and unchanged raw evidence. Run `python3 check_derived_work.py` for an offline count consistency check.
