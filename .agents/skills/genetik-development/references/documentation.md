# Documentation and examples

- Start user documentation with a short path by audience: first build, first
  consumer, then detailed API contracts and advanced capabilities.
- Keep README claims bounded to what the checked-in tests and retained evidence
  support. Link to one authoritative contract instead of duplicating it.
- Beginner examples should be complete, small, standard-library-only consumers
  of the installed target. Explain inputs, bounds, result status, and what the
  example does not guarantee.
- Detailed docs state defaults, resource limits, numerical semantics, supported
  environments, and known limitations. Keep scientific evidence immutable.
